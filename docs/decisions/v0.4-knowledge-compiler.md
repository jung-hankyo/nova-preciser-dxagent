# v0.4 decision record: the knowledge compiler (decisions 29-35)

Date: 2026-10-01 (v0.4.1 and v0.4.2 followed on 10-01 and 10-02). Implemented and unit-tested; never run against a live
LLM benchmark.

## Problem

In v0.3.1 the knowledge layer was the weakest part of the agent and the one most likely to produce confident errors.
Cards were drafted by an LLM (K = 3 self-consistency, optionally grounded in raw PubMed abstracts). Self-consistency
measured sampling noise, not truth; grounding checked that a quote existed, not that it supported the value, and then
raised confidence; the evidence pool had no hierarchy; drafts saw the current case; backgrounds were set by whichever
card first drafted a finding; the cache never expired; disease identity was an LLM name slug.

## Decisions

| # | Decision | Outcome |
|---|---|---|
| 29 | Compile knowledge offline from cited sources; offline coverage is the expected behavior | Adopted: offline default, live fallback off |
| 30 | MONDO / HPO ontology spine with local extension terms | Adopted |
| 31 | Full tree on the differential: siblings separated only once their parent leads | Adopted |
| 32 | Remove LLM-only card drafting from the code | Adopted |
| 33 | Retire the 8 hand-written seeds; cards come only from the compiler | Adopted (the seeds remain as test fixtures) |
| 34 | Confidence from a fixed tier table, no gold-set calibration | Adopted: no gold-set calibration |
| 35 | Derived backgrounds: rare-disease cards capped at 5% of the weight, floor 0.02 | Adopted |

## How a value is made

1. A source manifest entry (kind gives tier; edition, licence, file, diseases).
2. Passage selection by disease names (from the ontology) and frequency/accuracy cues.
3. LLM extraction: verbatim quotes and the numbers they contain, nothing computed; cached by file SHA-256.
4. Verification (code): the quote is verbatim in the source (normalized for case, spacing, dashes, PDF hyphenation);
   every number is in the quote; the quote names the finding or test (and the disease, for multi-disease sources).
5. Value (code): percent; n of m as (n + 0.5) / (m + 1), with m < 10 treated as a frequency class; sensitivity with
   1 - specificity as background; LR pairs converted; HPO classes; one unnegated frequency word in the clause naming the
   finding.
6. Reconciliation: tier, then precision, population directness, edition, sample size. Conflicts (more than 3x in odds)
   are recorded on the entry and discount it x0.9 only when they come from the same or a better tier.
7. Confidence: tier 1 numeric 0.95 / class 0.85 / qualitative 0.80; tier 2 0.85 / 0.75 / 0.70; tier 3 0.70 / 0.60 /
   0.55; times directness 1.0 / 0.9 / 0.8.

## Hierarchy semantics

A listed node with listed descendants stands for "this disease, any other subtype". Its bucket is the prior of its whole
subtree; children's buckets are clipped so that at least 10% of the subtree prior stays with the parent. The belief
update is unchanged (every listed node is one mutually exclusive hypothesis). The planner computes the error
probability and the pairwise confusion on a view that collapses each subtree into one node and expands it only while it
leads. The final diagnosis is still the top entry of the computed differential.

**What remains LLM-only:** contrast cards (the contrast step works well), bounded to existing codes and tests,
confidence at most 0.55, gap-filling only, never used by the reverse index.

## Verified

- Unit tests (no network, no API key), including an end-to-end compile in which a fabricated quote and a misreported
  number are rejected and the extraction cache makes a recompile LLM-free.
- On the real releases (MONDO and HPO 2026-09-01; HPO annotations 2026-09-02): indexes in about 5 s; 9,437 rare-disease
  cards and 12,574 new finding codes compiled in about 40 s; 7.6 MB gzipped; store load 3.6 s; reverse index 0.04 s per
  update after a 0.6 s first build. For ptosis, diplopia and weakness without fever, myasthenia gravis leads and the
  reverse index adds wound botulism, a recognized mimic.
- Simulation: `experiments/README.md` (v0.4 compiled knowledge).

## Later additions

- **v0.4.1:** local-document retrieval is the primary fallback for a disease with no card (on demand, same pipeline and
  cache as the offline compile); the online PubMed fallback is secondary and off. Live benchmark reporting: one summary
  file (`dxagent bench-report`) with module metrics and paired comparisons.
- **v0.4.2:** DeepSeek (OpenAI-compatible endpoint, thinking mode per spec) and OpenAI reasoning models; default profile
  DeepSeek agent plus OpenAI environment and judge; cost estimates and further module metrics in the report.

## Open

Common-disease coverage needs guideline, diagnostic-accuracy review and reference-text files supplied by the user
(`docs/SOURCES.md`); backgrounds for HPO-only findings are rare-disease averages, often at the 0.02 floor.
